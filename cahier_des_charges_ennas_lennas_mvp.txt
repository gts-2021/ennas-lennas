CAHIER DES CHARGES SIMPLIFIÉ
Plateforme « الناس للناس / Ennas Lennas »

Version : MVP
Objectif : lancer une plateforme simple, fiable et évolutive de mise en relation entre personnes ayant besoin d’aide et personnes souhaitant aider.

============================================================
1. PRÉSENTATION DU PROJET
============================================================

Nom :
الناس للناس – Ennas Lennas

Concept :
Créer une plateforme web permettant à une personne ou une famille de soumettre une demande d’aide.

La demande est vérifiée par l’équipe « Ennas Lennas » avant publication.

Les visiteurs peuvent ensuite consulter les cas publiés et proposer leur aide.

La plateforme ne promet pas de financer ou de résoudre toutes les situations.
Elle agit principalement comme intermédiaire entre le demandeur et les personnes souhaitant aider.

Exemples de demandes :
- médicaments ;
- alimentation ;
- vêtements ;
- fournitures scolaires ;
- équipement ;
- aide ponctuelle pour une famille ;
- autre besoin social validé par l’équipe.

============================================================
2. POSITIONNEMENT
============================================================

La plateforme Ennas Lennas n’est pas principalement une plateforme de gestion de catastrophes ou de convois humanitaires.

Son fonctionnement est centré sur des cas individuels ou familiaux pouvant exister toute l’année.

Exemple :

Personne dans le besoin
        |
        v
Soumission d’une demande
        |
        v
Vérification par l’équipe
        |
        v
Publication du cas
        |
        v
Partage sur le site / Instagram
        |
        v
Une personne propose son aide
        |
        v
Mise en relation
        |
        v
Suivi puis clôture du cas

============================================================
3. OBJECTIFS DU MVP
============================================================

Le MVP doit permettre de :

1. Centraliser les demandes reçues actuellement sur Instagram.
2. Éviter de gérer toutes les demandes dans les messages privés.
3. Vérifier les demandes avant publication.
4. Publier uniquement les informations nécessaires.
5. Permettre aux visiteurs de rechercher les cas disponibles.
6. Permettre à une personne de proposer son aide.
7. Suivre le statut de chaque demande.
8. Faciliter le partage des cas sur Instagram, WhatsApp et autres réseaux.

Le MVP ne doit pas gérer directement les paiements ou collecter de l’argent.

- modifier un cas ;
- clôturer un cas ;

- consulter les personnes ayant proposé leur aide.

- alimentation ;
- vêtements ;
- scolarité ;
- logement ;
- équipement ;
- autre.

Étape 2 – Informations

- prénom ;
- nom ;
- téléphone ;
- wilaya ;
- commune.

Étape 3 – Description

- titre ;
- description détaillée ;
- urgence ;

- prénom ;
- téléphone ou email ;
- message ;
- type d’aide proposé.

- acheter le produit demandé ;
- fournir une partie du besoin ;
- fournir le matériel ;
- aider au transport ;
- autre.

Après envoi :

la proposition apparaît dans l’espace administration.

6. WORKFLOW D’UNE DEMANDE
============================================================

Statuts recommandés :

SUBMITTED
Demande reçue.

UNDER_REVIEW
En cours de vérification.

NEED_MORE_INFO
Informations complémentaires demandées.

APPROVED
Demande validée.

PUBLISHED
Cas visible publiquement.

IN_PROGRESS
Une aide est en cours.

COMPLETED
Besoin satisfait.

CLOSED
Dossier clôturé.

REJECTED
Demande refusée.

CANCELLED
Demande annulée.

Workflow principal :

SUBMITTED
   |
   v
UNDER_REVIEW
   |
   +----> NEED_MORE_INFO
   |          |
   |          v
   |      UNDER_REVIEW
   |
   +----> REJECTED
   |
   v
APPROVED
   |
   v
PUBLISHED
   |
   v
IN_PROGRESS
   |
   v
COMPLETED
   |
   v
CLOSED

12. SÉCURITÉ
============================================================

Principes obligatoires :

- HTTPS ;
- mot de passe administrateur chiffré/hashé ;
- authentification Spring Security ;
- contrôle des rôles ;
- limitation de taille des fichiers ;
- contrôle du type des fichiers ;
- fichiers privés non accessibles directement ;
- aucune donnée personnelle sensible publiée automatiquement ;
- logs des actions administratives ;
- protection anti-spam sur les formulaires.

Ajouter un CAPTCHA seulement si nécessaire.

============================================================
14. CE QUE LE MVP NE FAIT PAS
============================================================

Pour garder le projet simple :

PAS de paiement en ligne.

PAS de portefeuille électronique.

PAS de microservices.

PAS d’Elasticsearch au début.

PAS d’application mobile native.

PAS d’intelligence artificielle complexe.

PAS de système automatique de validation des bénéficiaires.

PAS d’intégration WhatsApp complexe au MVP.

Toutes ces fonctionnalités pourront être ajoutées plus tard si elles deviennent utiles.

18. CRITÈRES DE RÉUSSITE DU MVP
============================================================

Le MVP est terminé lorsque :

1. Une personne peut déposer une demande depuis son téléphone.

2. L’équipe reçoit la demande dans le back-office.

3. L’équipe peut vérifier la demande.

4. L’équipe peut accepter ou refuser la demande.

5. Une demande acceptée peut être publiée.

6. Les données privées ne sont jamais visibles publiquement.

7. Les visiteurs peuvent consulter les cas.

8. Un visiteur peut proposer son aide.

9. L’équipe peut consulter et traiter les propositions.

10. Un cas peut être marqué comme terminé puis clôturé.

============================================================
19. PHILOSOPHIE DU PRODUIT
============================================================

Le cœur de « الناس للناس » doit rester très simple :

Une personne a besoin d’aide.

Une autre personne peut aider.

La plateforme permet de les rapprocher de manière organisée, respectueuse et transparente.

Le produit ne doit pas devenir inutilement complexe avant d’avoir validé ce besoin avec de vrais utilisateurs.
